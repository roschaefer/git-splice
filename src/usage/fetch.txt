NAME
    git-splice-fetch - Fetch splice upstreams

SYNOPSIS
    git splice fetch [--upstream <name>] [--branch <name> --track | --no-track] [path...]

DESCRIPTION
    Fetches every branch of each splice's upstreams, in parallel (at most
    8 at a time) and each upstream once, and reports when the branch a
    splice syncs with has moved. Branches deleted upstream are pruned.

    See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#description

OPTIONS
    <path>...
        Fetches only the upstreams of these splices, by their folders.
        Without paths, every splice's.

    --upstream <name>
        Fetches only this one of the upstreams the splice's .splice names.
        Without it, a splice with several upstreams has each fetched.

        See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#--upstream

    --branch <name> --track
        Also tracks that upstream branch on the current branch, without a
        pull or push: from then on, every command syncs the splice with it
        there, and 'git splice status' compares with it. See 'git splice
        merge --help'.

        See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#branch-tracking

    --no-track
        Stops tracking one, so the splice syncs with the branch named like
        the current one again.

        See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#branch-tracking

    See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#options

REFS
    The branches go to refs/splices/<key>/heads/*, where <key> is the
    upstream's key in this repository, e.g. lib for
    https://github.com/x/lib.git -- by URL, there is no Git remote; 'git
    splice key' prints and renames keys.

    See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#refs

GIT LFS
    Where the commit a merge would take stores files in Git LFS, also
    downloads their content from the upstream's LFS server, which the
    monorepo's doesn't have yet; clone and pull do so too. The monorepo's
    next push uploads it to the monorepo's. With GIT_LFS_SKIP_SMUDGE=1, or
    where Git LFS isn't set up to check out content, files stay pointers
    and nothing is downloaded. merge downloads nothing: it refuses when
    content it would check out isn't here.

    See also: https://git-splice.roschaefer.de/docs/command-reference/fetch/#git-lfs
